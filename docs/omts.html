omts 承载登录与账号、设备注册、终端会话与 P2P 信令。本页覆盖形态选择、从零部署、启动参数、网络要求与日常运维。 omts carries accounts, the device registry, terminal sessions and P2P signaling. This page covers topology, a from-scratch deploy, the startup reference, networking, and operations.

02部署Deploy

2.1 主机准备2.1 Host preparation

一台 Linux 主机（任何能跑 docker 的发行版），一个解析到它的域名，TLS 在 nginx 侧（或你的 CDN/LB）终结。目录与属主：One Linux host (any distro that runs docker), a domain pointing at it, TLS terminated at nginx (or your CDN/LB). Directories and ownership:

sudo mkdir -p /opt/omts/{bin,data,mysql-data} && cd /opt/omts
sudo install -d -o 65532 -g 65532 data          # omts 容器内 UID（bootstrap 密码写在这里）# omts container UID (bootstrap password lands here)
sudo install -d -o 999 -g 999 mysql-data         # MySQL 容器内 UID# MySQL container UID
属主别配错Mind the owners — data/ 写不进时 omts 会反复重启（fail-closed：bootstrap 密码必须能落盘）；MySQL 指到错误属主同样起不来。容器起来又退出，先查这两处属主。 if omts cannot write data/ it crash-loops (fail-closed by design: the bootstrap password must land on disk); MySQL refuses a wrong owner the same way. A container that exits right after start — check these two first.

端口：omts 只监听 127.0.0.1（默认 8443，被占就换并同步 nginx）；MySQL 只绑 loopback；公网只暴露 443（nginx）。完整端口矩阵见网络与 P2P。Ports: omts listens on 127.0.0.1 only (default 8443 — pick another if taken and update nginx); MySQL binds loopback; the public surface is 443 (nginx) alone. See Network & P2P for the full matrix.

2.2 MySQL2.2 MySQL

独立 compose project——这样重启 omts 永远不影响数据库：A dedicated compose project — restarting omts never touches the database:

# docker-compose.mysql.yml# docker-compose.mysql.yml
services:
  mysql:
    image: mysql:8.4
    command: --bind-address=127.0.0.1 --mysqlx=OFF
    environment:
      MYSQL_ROOT_PASSWORD: <root-password>
      MYSQL_DATABASE: omts
      MYSQL_USER: omts
      MYSQL_PASSWORD: <db-password>
    volumes: [ "./mysql-data:/var/lib/mysql" ]
    ports: [ "127.0.0.1:3306:3306" ]
    mem_limit: 400m          # 小内存主机建议限制# recommended on small hosts
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1"]
      interval: 5s
      retries: 12

$ docker compose -f docker-compose.mysql.yml -p omts-mysql up -d
# 3306 被本机其他库占用时加 # port 3306 taken on the host? add --port=3307 # 并同步连接串# and mirror it in the DB URL

2.3 下载并校验 omts2.3 Fetch and verify

从 GitHub Releases 取当前版本的 omts-linux-<arch>（国内主机可用 Gitee 镜像加速，但摘要仍以 GitHub 为准）：Grab omts-linux-<arch> for the current version from GitHub Releases (hosts in China can use the Gitee mirror for speed — verify digests against GitHub):

REL=https://github.com/oh-my-term/release-omts/releases/latest
curl -LO $REL/SHA256SUMS.txt

omts-linux-x86_64: OK

2.4 运行 omts2.4 Run omts

# .env — 密钥用 # .env — secrets via openssl rand -hex 32; chmod 600
OMT_JWT_SECRET=<random-64-hex>          # 登录令牌签名密钥# signs login tokens
OMT_CRYPTO_SECRET=<random-64-hex>       # 应用层加密密钥# app-layer encryption
OMT_REG_TOKEN=<random-64-hex>          # 节点间注册令牌# inter-node registry token
OMT_DB_URL=mysql://omts:<db-password>@127.0.0.1:3306/omts
OMT_SERVER_URL=https://omts.example.com   # 对外地址（OAuth 回调校验用它）# public origin (OAuth redirect validation)
OMT_TRUST_PROXY=true                      # 在 nginx 之后，取真实客户端 IP# behind nginx; real client IPs

# docker-compose.yml# docker-compose.yml
services:
  omts:
    image: debian:bookworm-slim        # 只做运行环境# runtime only
    entrypoint: ["/omts/bin/omts"]
    env_file: .env
    network_mode: host                  # 只听 loopback，简单直接# loopback-only listener
    cap_drop: [ALL]
    user: "65532:65532"
    volumes: [ "./bin:/omts/bin:ro", "./data:/omts/data" ]
    restart: unless-stopped

$ docker compose up -d

双节点：两个节点用不同的 OMT_NODE_ID（1 / 2）与监听端口，共享同一个 MySQL；重启逐台滚动，给在线会话留 drain 时间（compose 里 stop_grace_period: 75s），前面挂 LB。Two nodes: distinct OMT_NODE_ID (1/2) and ports per node over the SAME MySQL; restart one node at a time and give live sessions drain time (stop_grace_period: 75s) behind an LB.

2.5 nginx 入口2.5 nginx ingress

omts 自己不回 CORS 头，跨源调用的白名单在 nginx 配。路由合同：omts never emits CORS headers itself — the allowlist lives in nginx. Routing contract:

路径Path 去处 / 说明Target / notes
/api/ /auth/ 反代 omts；CORS 允许你的站点 origin 与 omtn 客户端 origin（http(s)://tauri.localhost、tauri://localhost、http://omt-web.localhost）；加 Vary: Origin；preflight 回 204proxy to omts; CORS allows your site origin plus the omtn client origins (http(s)://tauri.localhost, tauri://localhost, http://omt-web.localhost); send Vary: Origin; answer preflights with 204
/ws/ 反代 omts + WebSocket upgrade 头；超时给足（终端长连接，如 3600s）；此处不做 CORS（omts 自己校验 ws origin）proxy to omts with upgrade headers; generous timeouts (terminal sessions, e.g. 3600s); no CORS here (omts validates ws origins itself)
/healthz 反代 omts（存活探活）proxy to omts (liveness)
/oauth-callback* 静态页（见下）；Cache-Control: no-storestatic page (below); Cache-Control: no-store
/ 仅 API 形态：302 官网；完整形态：omta 静态目录API-only: 302 to the marketing site; full: the omta static root

顺手加上：client_max_body_size 10m（文件上传）、HSTS。要用飞书 / Google / GitHub 登录，还需部署 oauth-callback.html（从源码仓 web/src/oauth-callback.html 的构建产物取，与服务器同版本）。它带内联脚本——若在 nginx 层下发 CSP，script-src 哈希要按文件原始内联块字节（含首尾空白）sha256-base64 计算，页面升级后必须重算，否则被 CSP 拦死。管理后台 admin.html 同样出自构建产物（如挂 /admin.html）——建议限制到运维网段，或配置完成后撤下。While you are in there: client_max_body_size 10m (uploads) and HSTS. feishu / Google / GitHub sign-in additionally needs oauth-callback.html deployed (from the source repo's web/src/oauth-callback.html build output, same version as the server). It carries inline scripts — if nginx serves a CSP for it, the script-src hashes are sha256-base64 over the file's RAW inline blocks (leading/trailing whitespace included); recompute on every page change or CSP kills it. The admin console admin.html deploys the same way (e.g. at /admin.html) — restrict it to your ops network, or take it down once configuration is done.

$ docker compose ps && docker compose logs omts | tail -5

$ sudo cat data/bootstrap-admin-password.txt   # 0600，三行：username / password / hint# 0600, three lines: username / password / hint
password: xY7!…

# 管理员登录是根级路由（不带 /api/v1 前缀）：# admin login lives at the root route (no /api/v1 prefix):
$ curl -s https://omts.example.com/auth/login \
    -d '{"username":"admin","password":"…"}'   # → { "token": "…" }# → { "token": "…" }

# 建日常账号（不要日常用 admin）：# create a daily account (do not use admin daily):
$ curl -s https://omts.example.com/api/v1/admin/users \
    -H "Authorization: Bearer $TOKEN" \
    -d '{"username":"alice","display_name":"Alice","password":"…","role":"user"}'
bootstrap 密码只出现一次The bootstrap password appears once — 首次登录后立即改密（PUT /api/v1/user/password）。若它在操作中暴露过——贴进聊天、留在终端回滚里——必须立刻轮换。 change it right after first login (PUT /api/v1/user/password). If it was ever exposed — pasted into a chat, left in a scrollback — rotate it immediately.

2.7 验证2.7 Verify

$ curl -s https://omts.example.com/healthz
{"status":"ok","version":"…","draining":false}
$ curl -s -o /dev/null -w '%{http_code}\n' https://omts.example.com/api/v1/version   # 404 = 未知路由，正常# 404 = unknown route, expected
$ curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' https://omts.example.com/   # 302 官网（仅 API 形态）# 302 marketing site (API-only)
$ curl -s -o /dev/null -w '%{http_code}\n' https://omts.example.com/oauth-callback/feishu  # 200# 200

再拿真实客户端连一次：登录、看到设备列表。命令行探针全绿 ≠ 进程健康——部署后盯着 docker compose ps 稳定跑一两分钟，/healthz 连续三次一致才算完。Then connect a real client once: sign in, see the device list. Green CLI probes ≠ a healthy process — watch docker compose ps stay up for a minute or two and /healthz agree with itself three times in a row before calling it done.

03接入设备Onboard devices

日常路径是在客户端里点「添加机器」，它会生成带一次性令牌的安装命令；这一节是同一协议的 API 视角，供自动化脚本用。令牌是两段式：The daily path is the client's "Add a machine" button, which generates an install command with a one-time token; this section is the same protocol from the API side, for automation. The token exchange is two-step:

# 1）用账号令牌签发 setup token# 1) mint a setup token with the account JWT
$ curl -s -X POST https://omts.example.com/api/v1/devices/setup-token \
    -H "Authorization: Bearer $TOKEN" -d '{}'
{"setup_token":"…"}

# 2）用 setup token 换一次性注册令牌（GET，消费即失效）# 2) trade it for a one-time registration token (GET; consumed on read)
$ curl -s https://omts.example.com/api/v1/devices/setup-token/<setup_token>
{"reg_token":"…"}

# 3）被纳管机器上注册（用的是第 2 步的 reg token）# 3) register on the managed machine (with the STEP-2 reg token)
$ omtc register https://omts.example.com/<reg_token>

401 多半是把 setup token 当注册令牌用了，或它已被消费。注册成功后设备的 16 位指纹在 ~/.omt/bootstrap-commit；客户端首次连接时填入指纹完成 TOFU 信任锚定。A 401 usually means the setup token was used where the registration token belongs, or it was already consumed. After registration the device's 16-character fingerprint lives at ~/.omt/bootstrap-commit; enter it on first connect to anchor TOFU trust.

04启动参数Startup reference

omts 的参数都能以 OMT_<NAME> 环境变量传入（密钥类参数只认环境变量，拒绝命令行——参数会经 /proc 与 docker inspect 泄漏）。常用项：Every flag also reads from an OMT_<NAME> environment variable (secret-bearing flags are env-only — args leak through /proc and docker inspect). The ones you will actually set:

参数 / 环境变量Flag / env 说明Notes
--listen监听地址，默认 127.0.0.1:8443（只听 loopback）。反代终结 TLS 时配合 --allow-plaintext-listen 绑非 loopbacklisten address, default 127.0.0.1:8443 (loopback only). Pair with --allow-plaintext-listen to bind non-loopback behind a TLS-terminating proxy
OMT_DB_URLMySQL DSN（mysql://user:pass@host:3306/db），仅环境变量MySQL DSN (mysql://user:pass@host:3306/db), env-only
OMT_JWT_SECRET登录令牌签名密钥；留空自动生成（重启即全员下线，固定部署务必显式设置并备份）signs login tokens; auto-generated when empty (a restart then signs everyone out — set it explicitly and back it up)
OMT_CRYPTO_SECRET存储凭据（TOTP / OAuth secret）的加密密钥；丢失即加密数据不可恢复encrypts stored credentials (TOTP / OAuth secrets); losing it makes that data unrecoverable
OMT_REG_TOKEN节点间注册令牌（多节点共用）inter-node registration token (shared across nodes)
OMT_SERVER_URL对外可达地址（OAuth 回调校验、绝对链接生成用它）the externally reachable origin (OAuth redirect validation, absolute URLs)
OMT_TRUST_PROXY在可信反代之后时置 true（读 X-Real-IP 做限流与审计）。反代必须每请求覆写该头；omts 直接暴露给不可信客户端时必须为 falsetrue when behind a trusted proxy (reads X-Real-IP for rate limits and audit). The proxy MUST overwrite that header on every request; must be false if untrusted clients reach omts directly
OMT_NODE_ID多节点节点标识；双节点部署必须显式指定（1 / 2）node identity; two-node deployments MUST pin it (1 / 2)
OMT_STUN_LISTEN / OMT_STUN_PUBLIC_ADDRP2P STUN 的 UDP 绑定与公网地址（成对出现）。留空 = 关闭 STUN，直连退化为同网候选the STUN UDP bind and public address (set together). Empty = responder off; direct paths degrade to host candidates
OMT_METRICS_ALLOW_CIDRS/metrics 的 CIDR 白名单，逗号分隔；留空对远端完全关闭comma-separated CIDR allowlist for /metrics; empty disables it for all remote callers
OMT_INACTIVITY_ENABLED 等闲置账号清理（disable→delete）开关与天数族；私有部署默认关the inactivity account lifecycle (disable→delete) switch and day thresholds; off by default for private deployments
--tls-cert / --tls-key自带 TLS（不经反代时）native TLS (when not fronted by a proxy)

其余项（WebSocket 帧上限、飞书 webhook、测试通道等）见 omts --help；omts config 子命令可直接改数据库里的运行时配置（绕过 HTTP 管理接口）。The rest (WebSocket frame caps, the feishu webhook, test endpoints…) live in omts --help; the omts config subcommand edits runtime values in the DB directly, bypassing the HTTP admin API.

05网络与 P2PNetwork & P2P

端口Port 协议Proto 暴露面 / 用途Surface / purpose
443TCP公网 · nginx 入口（API / ws / 静态页）public · nginx ingress (API / ws / static pages)
3478 （默认，可改）(default, changeable)UDP公网 · STUN 打洞应答。端口不必是 3478——地址随 P2P 授权下发，客户端零改动；选云安全组已放行的即可。主机防火墙与云安全组两层都要放public · the STUN responder. Need not be 3478 — the address travels with the P2P grant, clients need no change; pick one your security group already allows. Open it in BOTH the host firewall and the cloud security group
8443TCPloopback · omts 监听（nginx 反代指向它）loopback · the omts listener (nginx proxies to it)
3306TCPloopback · MySQL（多节点时只对节点网段开）loopback · MySQL (open to the node subnet only when multi-node)

直连成功时终端流量不经过服务器（STUN 只做打洞信令）；打不通自动回退中继，中继默认开启——STUN 端口没放行不影响可用性，只是直连成功率下降。判断 UDP 端口可达要用外部视角复核：家庭宽带的 UDP 探测常把可达口误报为不通。When direct P2P works, terminal traffic never touches the server (STUN only aids hole punching); failed attempts fall back to the relay, which is on by default — a closed STUN port never breaks connectivity, it only lowers the direct-hit rate. Re-check UDP reachability from an external vantage point: home-broadband probes routinely mislabel open ports as blocked.

06日常运维Operations

升级与回滚Upgrades and rollback

下载新二进制并校验 → 旧版挪为 bin/omts.v<ver> → 新版就位 → docker compose up -d（重建容器）。数据库迁移在启动时自动执行。回滚 = 拷回旧文件再重启。双节点逐台滚动，确认一台健康再动下一台。Fetch and verify the new binary → move the old one to bin/omts.v<ver> → put the new one in place → docker compose up -d (recreates the container). DB migrations run on boot. Rollback is copying the old file back and restarting. For two nodes, roll one at a time and let it report healthy before touching the next.

密钥与备份Secrets and backups

OMT_JWT_SECRET / OMT_CRYPTO_SECRET 丢失 = 所有登录态与加密存储失效——离线备份 .env 与 MySQL 数据卷。轮换 JWT 密钥会使全部客户端重新登录（服务端用户与设备数据不受影响）。Losing OMT_JWT_SECRET / OMT_CRYPTO_SECRET invalidates every session and all encrypted storage — back up .env and the MySQL volume offline. Rotating the JWT secret signs everyone out (server-side users and devices are unaffected).

企业登录（OAuth）Enterprise sign-in (OAuth)

飞书 / 钉钉 / Google / GitHub 在管理后台（admin.html → OAuth Providers）配置。关键点：除桌面客户端回调外，必须把服务器自己的 https://<域名>/oauth-callback/<provider-id> 注册为回调地址——移动端系统浏览器登录走的就是它，缺了移动端就无法登录。feishu / dingtalk / Google / GitHub are configured in the admin console (admin.html → OAuth Providers). Key point: besides the desktop callback, you MUST also register the server's own https://<domain>/oauth-callback/<provider-id> as a redirect URI — the mobile system-browser sign-in relies on it; without it mobile sign-in cannot work.
